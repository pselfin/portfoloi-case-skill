# Видеообход сайта

По ссылке на готовый сайт снять два ролика: десктоп и мобильный. Курсор виден, жест подписан, страницы листаются, меню открывается.

Это не `video-shotcraft`. Тот скилл монтирует рекламный ролик из кадров. Здесь — живой обход сайта, его делает только `record.js`. Браузерными инструментами видео не писать: они не сохраняют ролик в проект.

## Вход

Обязательна ссылка. Если её нет — спросить, не угадывать адрес.

## Куда писать

```
cases/<domain>/video/tour.mp4
cases/<domain>/video/tour-mobile.mp4
cases/<domain>/video/route.json
```

`<domain>` — hostname без `www.` и без порта. Кириллический домен — юникодом. Папку `cases/<domain>/` не чистить: `case.md` и `screenshots/` не трогать. Повторный запуск перезаписывает только файлы в `video/`.

## Порядок

1. Из корня воркспейса запустить запись. Скрипт сам ставит диагноз, если нет `puppeteer-core` или `ffmpeg`.
2. Если страница пустая или это проверка «вы не робот» — один повтор с `--headful`. Не помогло — остановиться и сказать, что сайт закрыт для автоматической съёмки.
3. Проверить оба файла и кадры из них. Смотреть глазами, через Read, не по размеру файла.
4. Временные кадры проверки удалить. В `video/` остаются только два ролика и `route.json`.

```
node .cursor/skills/portfolio-case-video/record.js --url https://example.ru/
```

Полезные флаги:

- `--plan` — напечатать маршрут и выйти, ничего не записывая.
- `--pages "url1;url2"` — свой список, если автовыбор промахнулся. Первый адрес снимается как главная.
- `--headful` — видимый Chrome, если сайт режет headless.
- `--out cases/<domain>/video` — другая папка.
- `--ua "..."` — свой User-Agent.

Нужны Node.js 18+, системный Chrome и `ffmpeg` в PATH. Chrome ищется сам; иначе `CHROME_PATH`. ffmpeg — `FFMPEG_PATH` или `winget install Gyan.FFmpeg`. `puppeteer-core` скрипт ищет сам и подсказывает установку:

```
npm install --prefix .cursor/skills/portfolio-case-video puppeteer-core
```

## Что делает ролик

Оба ролика идут по одному маршруту из `route.json`. Без музыки. Десктоп обычно 1,5–3 минуты, мобильный обычно 2–4. Главная до конца может выйти за эту вилку. Жест не обрывается посередине.

Десктоп — 1920×1080. Мобильный вьюпорт — 767×1660, та же пропорция телефона, что у кадров `portfolio-case`, мобильный User-Agent и тач. В файле ширина 768: H.264 просит чётное число, справа один пиксель поля. На мобильном меню открывается бургером.

Анимации не отключаются. Курсор — стрелка поверх страницы. Субтитры вшиты в кадр: «Свайп», «Клик», «Наведение». «Наведение» только на десктопе.

В начале главной, если это есть на сайте: принять cookie, открыть и закрыть чат, показать плавающие мессенджеры, прокрутить до кнопки «наверх» и нажать её. Формы не заполняются.

Дальше не больше шести страниц: главная, каталог или другой список, одна карточка из него, услуга, статья, контакты. Чего нет — пропуск. Юридические страницы, вход, корзина, поиск и пустые страницы не открываются.

Прокрутка:

- Главная — до конца. Потолка нет. Бесконечная лента обрывается примерно после 40 экранов, это защита, не лимит обычной страницы.
- Каталог с однотипными карточками — до 4 экранов.
- Остальные внутренние страницы — до 7 экранов на десктопе и до 12 на мобильном.

На десктопе несколько наведений на кнопки и карточки. Пункт с выпадающим меню сначала накрывается курсором.

## Проверка

`ffprobe` показывает 1920×1080 и 768×1660, кодек H.264. Вытащить по 3–4 кадра: начало с баннером или виджетом, кадр с субтитром, переход на внутреннюю страницу, конец.

```
ffmpeg -y -ss 2 -i cases/<domain>/video/tour.mp4 -frames:v 1 %TEMP%/tour-check.png
```

Кадр годный, если курсор в кадре, подпись читается, контент загружен, это не белый экран и не проверка на робота.

## Ответ пользователю

Дать пути к `tour.mp4` и `tour-mobile.mp4` и короткий маршрут из `route.json`: тип страницы и адрес.
